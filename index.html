An alarm that slowly stops noticing the problem

A big machine in a factory has sensors on it. A computer program watches those sensors and learns what normal looks like. It keeps learning every day, so it can keep up as the machine gets older.

If the machine is slowly breaking while the program is learning, the program learns the breaking as normal too, so it stops seeing it as a problem.

The sliders below let you do this to it. Every number on this page is measured from a real experiment.

PART 1

The alarm gets used to the problem

The dark dots are the machine working normally, the orange ones are the machine with a small problem. The cross is where the program currently thinks normal is. Drag the slider to feed it more of the broken data.

The two numbers on the right run from 0 to 1. One means the alarm is at full strength, zero means it is gone. Watch them as you drag. The alarm for the problem the program is learning falls to 0.70, about a third weaker. For problems it never learned about, it stays near 0.90. So the program still does its job. It just goes blind to the one problem the machine actually has, which is why nobody notices anything is wrong.

PART 2

Getting Fault 3 back

One problem, called Fault 3, is almost invisible to the program. There is a physics check that can find it. But everything in a plant slowly drifts as it ages, and the drift looks like a problem too, so the alarm goes off all the time. Drag the drift slider up, then turn the switch on.

Can it see past the drift?

With the switch on, Fault 3 is found in 83 runs out of 100 even while everything is drifting, and 85 out of 100 when it is not. On machines that were never used while we were building this, it goes off on a healthy machine 11 times in 100 (the true rate is somewhere between 6 and 19 in 100). With the switch off, the faulty readings sit right on top of the healthy drifting ones, so there is no setting that separates them.

PART 3

Comparing the alarm with an older copy of itself

Keep a frozen copy of the program from before it started learning, and check the two against each other. If the problem it stopped noticing comes back, the two copies disagree within about 9 minutes. A program that has already gone blind can also be fixed using the frozen copy, going from 0.32 back up to 0.79 on the same dial as Part 1. Open the second demo →

Where these numbers come from
  • Every dial is a measurement from an experiment we wrote down before we ran it.
  • The tests run on a computer model of a chemical plant that many researchers use, so results can be compared. Its name is the Tennessee Eastman process. We ran every test three times from different starting points, so a good result cannot just be luck.
  • We wrote down and registered the Fault 3 result, 0 to 83 out of 100, before we ran it. The 11-in-100 false alarm figure comes from machines held back and never looked at while we were building this.
  • The dots and humps are drawn simply, to make the shape of the idea clear.
  • The code, the data and the lab notebook are behind the other QR code on the poster.
