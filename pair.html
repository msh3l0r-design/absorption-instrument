Comparing the alarm with an older copy of itself

The program never stops learning from its machine. That is what keeps it useful as the machine ages, and it is also the way it can be taught the wrong thing. The fix is simple: save a copy of the program from before it started learning, and keep checking the new one against the old one. Every number on this page is measured from a real experiment.

PART 1

Two copies of the same program

One copy keeps learning every day. The other was saved on the first day and is never changed again. You can only tell that you have changed if you remember what you used to be like.

When a slow problem hides in the data the program learns from, the learning copy can quietly start treating that problem as normal. Nothing about the learning copy on its own will ever show this. The old copy is the only outside witness.

PART 2

Watching the two copies disagree

Both copies guess what the machine will do next. Then we compare how wrong each guess was. Pick a day and see what happens.

PART 3

Undoing the damage

Once the program has learned a problem as normal, its guesses are pushed in one particular direction, and we can measure that direction almost exactly. The old copy is what tells us which way it moved. So we just push it back. The program is not retrained and nobody has to label anything. Drag the slider.

A program that had gone blind sat at 0.32, which means it was rating the failing machine as healthier than a healthy one. Pushing it back brings it to 0.79, and that is better than throwing it away and starting again, which only reaches 0.69. It has to be this machine's own old copy. A copy from a neighbouring machine does not work, and on a program that was never damaged this does nothing at all. We measured both of those limits too.

What did not work, kept here on purpose

This only works for one family of problems so far. Those are the ones that shift the sensor readings up or down, and for those it works every time we tried, spotting the problem in about 9 minutes. There is a second family, where the fault spreads itself thinly across many sensors instead. We tried four different ways to catch those, wrote down beforehand what would count as success, and all four failed. Those are handled by the other two methods on the poster instead. Everything here is a computer model of a plant, run three times over. The next step is to try it on a real one. We keep the failures on the page next to the successes, because that is the only reason the successes are worth anything.
